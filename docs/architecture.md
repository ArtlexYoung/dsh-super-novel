# 当前架构

当前 `0.0.5` 提供写作预设、作品存储、章节编辑、生成候选、作者采纳、正文历史和冲突恢复。事实回填和独立审校尚未实现。

## 模块

## 启用流程

1. profile 加载 bundle，注册 Host 服务和客户端侧栏。
2. 打开侧栏，通过 Remote 查询状态，不写文件、不调用模型。
3. 用户点击启用后，安装器检查目标目录，取得排他锁并写入预设及归属记录。
4. 宿主发现预设，用户在会话中选择 `Super Novel · 小说生成`。
5. 写作提示词加入该 Agent；模型、权限、工具和会话仍由宿主管理。

预设 ID 为 `dsh-super-novel`，由目录名确定。安装不改变默认模式，也不替换其他预设 roots。已有版本或文件不符时显示冲突，不自动覆盖。

## 构建与边界

构建生成 Host、Client 和 Typert/Remote 文件，安装包直接携带这些产物。客户端使用宿主服务，不另建模型运行时。

作品身份和章节身份使用稳定 UUID。标题只作展示，正文保存为 Markdown。索引包含格式版本、作品 revision 和各章 revision/hash。浏览器不指定本机路径，Host 从会话 header 获取 workspace；只读策略阻止写入，远程 FS 被拒绝。

保存先写完整恢复记录，再替换正文和索引，最后发布完成记录。失败保留旧稿与候选；新实例读取未完成状态，作者显式恢复。恢复只接受已记录的旧/新文件，第三种内容触发冲突。同书写入有跨进程锁，重复操作返回原结果。只读查询不创建文件，也不会恢复写入。

浏览器草稿按 workspace、作品和章节保存，携带原始版本和哈希。正式保存不依赖浏览器数据或聊天记录。外部编辑器不参与插件锁，多文件保存不是跨文件原子事务。

历史直接读取已完成保存记录，分页返回最多 100 项，不另建历史写事务。旧稿恢复与冲突处理产生新 revision，重复操作复用原结果。冲突稿不可变，实际保存仍检查当前磁盘哈希。中断后出现第三种正文时，作者可核对两稿并确认正文；原提交记录先归档，再替换待恢复记录，随后完成普通保存。没有该确认时不会覆盖第三种正文。

生成任务绑定 workspace、作品、章节、基线版本/哈希、授权选区和作者资料快照。模型只返回替换文本，选区外内容由程序原样拼接。候选状态与正文分离；采纳复用正文保存日志，完成记录用于识别中断后的重复采纳。查询不调用模型或自动恢复写入。

生成通过宿主 LLM 服务使用当前会话所选路由，没有工具、父聊天记录、额外文件读取或客户端 provider 请求。任务脱离浏览器请求运行，插件卸载、显式停止或超时会取消。只保留已收到的有效文本；没有明确完成、空输出和截断均不能采纳。缺失用量保持未知，不估算成实际账单。

提示词中的连续性检查、摘要和修改范围要求仍属于模型指导，不等于已实现事实回填、独立审校或修订验收。

历史技术验证主要覆盖 macOS Web；Desktop、Windows/Linux、热卸载和完整磁盘故障矩阵尚未验证。恢复限制见[使用说明](usage.md)。
