# P0 浏览器写作与截图验证

日期：2026-09-20。产品基线：`0.1.0-alpha.1` / `aad8021`；Harness：`0.1.5-rc.2` / `c291e7961a`。本批通过真实 Web 页面发送两次模型任务，验证正文显示、局部修改和侧栏；**写作质量并未全部通过**。不因消耗更多 token 拒收结果，也不把界面或请求成功当成文学质量通过。

## 环境与实际操作

macOS arm64、Node.js 24.18.1、Playwright 1.61.1 / Chromium headless。从本项目构建产物打包，在新的隔离 profile 安装 tarball，运行真实 Harness Web。没有修改日常 profile、参考仓库或执行市场发布。

浏览器依次打开「小说工作台」、点击启用、新建会话、选择 `Super Write · 小说写作`，通过输入框发送雨夜渡河场景，再发送局部修订。默认模型为 TokenHub `deepseek-v4.1-flash` / high，超时 180 秒、无自动重试。测试 profile 禁用自动模型标题；会话标题由首条用户消息截取，不消耗额外模型调用。设置会话的空完成事件只用于展示会话侧栏，不含生成正文。

事件证据确认 `agent-preset/selected=dsh-super-novel`，系统消息含实际写作指导；两个 turn 均 completed，各一个 assistant/message，无工具、失败尝试或重试。初始 `request/header` 为 high / `maxTokens=384000`，由适配器模型配置提供；第二轮沿用配置，没有额外 header 事件。本批没有人为缩减正文输出额度；上限不代表实际生成量，也不证明已验证 provider 的最大输出能力。

## 写作结果

| 任务 | 实际结果 | total tokens |
| --- | --- | ---: |
| 雨夜渡河起草 | 要求六段、900–1200 个汉字，实际十三段、759 个汉字，结构和长度不通过 | 2,407 |
| 指定段落修订 | 仅第九段变化，其余十二段逐字一致；替换段 179 个汉字，在 110–180 范围内 | 11,376 |
| 合计 | 两次真实请求，无重采样或挑选最佳稿 | 13,783 |

token 使用宿主报告的 totalTokens；缓存量不再次相加。reasoningTokens 未单独报告，不以 outputTokens 充当正文长度或推理用量。界面分别显示约 9 秒、42 秒，属于界面取整耗时，不作速度比较。局部修订消耗更多 token，仍按修改边界和文字结果评价。

原定第二题针对六段稿的第三段。首稿实际生成十三段，因此提交前明确改为引用实际第九段，并要求保留其余十二段，避免任务本身含糊。原任务、调整理由和真正提交的任务均保留；这不会改变首稿结构失败的结论。

以下为本轮执行者的定性审阅，不是独立审校或多人盲评：

- 正文保留左腕固定、右手吃力操作、少女畏水、药包防水、两人同行和结尾尚在河上的主要设定；没有揭露秘密身份或安排援兵。没有再次出现“超载却收钱就能上船”的因果矛盾。
- 首稿验货只写粗布未烂、不霉，抵船资的价值依据较弱。修订增加拆料、弹花铺收棉、换桐油和缆绳的用途，形成较具体的接受动机；具体兑换比例没有世界设定佐证，仍需作者确认，不能当成确定事实。
- 修订段沿用“反悔就扔河里”的威胁，与船夫精打细算的动机仍有张力。结尾药绳从六结变七结形成单一悬念，但绳结的识别依据和物件可能被动过的机会尚需后文兑现。
- 精确保留未授权段落通过；没有趁修订扩写到规定字数或重排成六段，这是本次局部授权的正确边界。首稿问题需另一个明确的修改任务处理。
