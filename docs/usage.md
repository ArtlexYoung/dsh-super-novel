# 使用说明

安装步骤见 [README](../README.md#安装)。以下说明适用于当前技术预览版。

## 启用与写作

打开带本地 workspace 的会话，在右侧栏选择「小说工作台」。输入作品名并新建作品，再输入章节名并新建章节。章节可改名、上移或下移；标题改变不会改变正文文件身份。

在章节编辑区写正文，点击保存。预览按原文显示，不执行 HTML。换会话、关闭侧栏或重启后，打开相同 workspace 即可读取作品。正文单章上限为 4 MiB UTF-8，作品最多 10,000 章；作品索引上限 4 MiB，单次保存记录上限 32 MiB。超限会拒绝处理，不截断。

聊天写作时展开「写作模式」，点击「启用小说生成模式」，随后在宿主模式选择器中选择 **Super Novel · 小说生成**。聊天回复不会自动写入章节，需要手工填入编辑区并保存。当前没有 AI 提案、自动字数检查、事实回填或独立审校。

只读会话可以查看正文，不能创建或保存。需要写入时使用宿主允许写 workspace 的会话；插件不会自动改变权限。

## 数据位置

启用时，插件向宿主第一个 `trust: user` 预设根写入 `dsh-super-novel/`。默认通常为 `$DSH_HOME/.agent-presets/dsh-super-novel/`；未设置 `DSH_HOME` 时通常位于 `~/.dsh` 下。自定义根支持绝对路径和 `~/`，相对路径会被拒绝。

预设目录内只有 `preset.yml`、`agent.cordis.yml` 和归属记录 `.dsh-super-novel.json`。

作品保存在当前 workspace 内：

```text
novels/<作品ID>/
  project.json                    # 标题、章节目录和版本
  chapters/<章节ID>.md             # 正式正文
  transactions/<操作ID>.json       # 已完成保存记录及原稿
  pending.json                    # 仅未完成保存时存在
```

建书中断时还可能存在 `novels/<作品ID>.creation.json`。不要直接改索引或保存记录来绕过版本检查。备份、迁移作品时复制整个作品目录；有未完成创建时也保留对应创建记录。

未保存输入保存在浏览器本地，按 workspace、作品和章节隔离。浏览器拒绝存储或容量不足时会提示，请立即保存或下载本地草稿。正式正文和保存记录在磁盘上，不依赖聊天历史。只查看侧栏不会创建目录或调用模型。

## 正文冲突与恢复

- 外部编辑后点击刷新或重新聚焦窗口，正文会重新读取。若已有本地草稿，先下载草稿，再读取磁盘版本并人工合并。
- 保存前发现版本或哈希改变时拒绝覆盖，本地草稿仍保留。已读取的外部编辑可以保存为新版本。
- 出现「恢复未完成的保存」时，点击恢复。只有文件符合记录中的旧版或新版，才继续完成保存；出现第三种内容时停止并保留现场。
- 提示忙碌但宿主已经退出时，先备份作品并确认所有写入进程都已退出，再用 `rmdir` 移除空的 `novels/<作品ID>/.write.lock/`；建书锁位于 `novels/.create.lock/`。不要抢占运行中的锁。

多文件保存不是跨文件原子事务。锁只协调本插件实例，外部编辑器不使用该锁；不要让外部程序与插件同时保存同一文件。普通冲突检测和阶段故障已测试，不宣称能抵御恶意目录替换或所有断电情况。历史查看、恢复旧稿和自动合并尚未提供。

## 启用失败

| 情况 | 处理方法 |
| --- | --- |
| 同名目录不属于插件、存在额外文件、文件被修改或版本不同 | 备份整个目录并检查差异。需要重装时，将旧目录移到预设根之外，再启用 |
| 归属记录有效，只缺少部分文件 | 点击「继续启用」 |
| 文件只写了一部分、归属记录损坏或缺失 | 保留并备份现场，将旧目录移出预设根后重新启用 |
| 提示正在启用，实际进程已退出 | 确认所有启用进程已退出，再用 `rmdir` 移除预设根下的空 `.dsh-super-novel.lock/` 目录 |
| 没有可写用户根或使用相对路径 | 检查宿主 roots 配置；插件不会自动修改配置 |

锁用于协调插件实例。不要在其他实例启用时移除锁。写入不是跨文件事务，中途失败会保留现场；路径检查不覆盖所有祖先目录，也不抵御其他程序同时替换文件。

## 升级

当前版本不自动迁移预设。先关闭使用旧模式的会话，备份旧预设并将其移出预设根；安装新包后重新启用，再对照备份处理自己的修改。不要修改归属记录来绕过冲突保护。

## 卸载

1. 关闭使用小说生成模式的会话。
2. 将用户预设目录备份并移到所有预设根之外。
3. 从安装时使用的 profile 移除插件，例如：

   ```sh
   dsh plugin --profile web remove dsh-super-novel
   ```

官方插件命令会同步 profile 的 bundle 清单。若手动管理 profile，还需移除 `dsh.profile.bundles` 中的 `dsh-super-novel`。

先卸载包会留下引用缺失包的预设，宿主可能显示不可用。重新安装相同版本可以恢复，也可按上述步骤移走残留预设。插件没有自动卸载清理钩子，也不会删除 workspace 中的作品。
