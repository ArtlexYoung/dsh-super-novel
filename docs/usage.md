# 使用说明

安装步骤见 [README](../README.md#安装)。以下说明适用于当前技术预览版。

## 启用与写作

打开带本地 workspace 的会话，在右侧栏选择「小说工作台」。点击顶部作品名或底部「更多」，输入作品名并新建作品，再在「目录」中输入章节名并新建章节。点击文档标题可改名，按 Enter 或确认按钮完成；「更多」中的「文档选项」提供上移、下移和读取磁盘版本。标题改变不会改变正文文件身份。

从目录打开文档默认进入「写作」。在编辑区写正文，点击保存或按 ⌘/Ctrl+S；按钮旁显示保存状态，下方显示非空白字数。预览按原文显示，不执行 HTML。换会话、关闭侧栏或重启后，打开相同 workspace 即可读取作品。正文单章上限为 4 MiB UTF-8，作品最多 10,000 章；作品索引上限 4 MiB，单次保存记录上限 32 MiB。超限会拒绝处理，不截断。

先保存正文，点击底部「助手」，在「生成设置」选择起草、续写、选段改写或润色，填写写作要求并生成。改写、润色前先在「写作」选中文字，切页保留选区。参考资料可主动填写，生成只读取这些资料和目标正文，不读取其他作品或聊天历史。

生成后设置自动收起，先展示候选。查看「候选正文」或「改动对照」，再采纳或拒绝；需要重写时展开「生成新候选」。重开文档可继续使用最近候选的要求和来源。候选在采纳前不改变正式正文；目标正文或所用来源变化后候选过期，无关章节编辑不影响它。前文顺序、事实选择、意图和状态也会重新检查。生成可停止，关闭侧栏或切换会话不会改任务归属。宿主退出后未完成任务不自动重发，收到的内容仍保留。空输出、截断和未完成候选不能采纳。

在目录切到「资料」，可生成故事种子、书卡、人物、世界、总纲、章纲和场景：

1. 点击「新建资料」，选择类型，填写想法与要求；名称可留空，系统会使用类型名并避免同名。
2. 可展开「选用来源」，勾选已有资料或保存正文。章纲、场景还可关联章节。不选来源也能从想法生成。
3. 点击「AI 生成资料」，请求成功后进入「助手」查看候选和改动对照，采纳后保存为资料。也可点击「手动创建模板」，直接回到「写作」填写。
4. 在「写作」读写资料，在「助手」修改要求并继续生成；要求留空时按资料类型生成。在「写作」选中文字后可改写或润色选区。手工修改先保存，切页不会丢失草稿。

资料有保存、历史、停止、拒绝和采纳入口。创建成功但生成未确认时，原请求保留，可重试而不重复创建；也可在「助手」重新生成。新建要求尽量保留在当前浏览器，清除浏览器数据会丢失这部分输入。重启后不会自动调用模型。

底部五个入口用于不同操作：

| 入口 | 用法 |
| --- | --- |
| 写作 | 正文编辑、预览和保存 |
| 目录 | 搜索、选章、新建章节或资料；资料可按类型和关联章节筛选，超过 100 项分页 |
| 资料 | 搜索同书已保存资料并只读查看，本章关联资料排在前面；需要修改时点击「编辑这份资料」 |
| 助手 | 生成、查看候选和改动对照，再采纳或拒绝 |
| 更多 | 作品管理、保存位置、备份恢复、资料库、本章意图、时间线与伏笔、事实与文风、审校和写作模式 |

窄侧栏一次展开一个工具，按 Esc 或点击关闭返回原位置；宽面板左侧保留目录。切换目录分类和筛选只改变列表，点击文档才开始编辑它。资料预览不改正文、不正式保存、不调用模型。工具切换和缩放保留原编辑器、选区、滚动和撤销；新建或导入后清除目录筛选。

生成只读取明确勾选的同书已保存内容，未保存输入不参与。空来源或未登记的外部修改会阻止生成；来源改变后旧候选过期。正文整理结果仍需核对，建议新增设定、未知项和正文已有信息应分开。规划不是已发生事实，普通资料不会更新带证据的事实记录，也不会自动授权文风。正文起草可在「选用已保存资料」勾选采纳后的资料。

「更多」中的「事实与文风」提供事实与摘要：显式提取候选，核对引用和知情范围后采纳；也可选择原文手动添加事实，局部回填不会算成全章完成。引用可定位回正文。提取不会修改正文，未采纳内容不进入事实。引用匹配不能证明语义正确，仍需作者核对。旧章改变后事实过期，需要重新提取。

生成下一章时可开启「使用前章事实」，选择读者或人物知情范围。读者事实不会自动进入人物知识，人物范围不使用读者摘要。缺失/过期回填或事实超过 128 KiB 时阻止该生成；关闭此选项时不保证长篇连续性。原文中的伤势、时间线、秘密等由事实候选表示，不宣称模型能完整识别全部信息。

在「更多」→「审校」选择已保存正文或待采纳候选，设置字数/段数范围后开始审校。字数是非空白 Unicode 码点数，段落按空行分隔；0 表示不设上限。模型分别检查连续性、人物、因果和语言，问题必须带匹配原文的引用。可定位原文、生成局部修订、查看改动、再次审校，再采纳。每条候选修订链最多两轮，不自动覆盖正文。没有资料、检查失败或未完成时明确显示依据不足或未知；未发现问题也不保证文学质量。

生成和审校使用当前会话的模型与宿主连接，不在浏览器配置凭证。单次输入上限 256 KiB UTF-8（包含正文、要求和资料），最多输出 8192 tokens，五分钟超时；超出输入范围会拒绝调用，不静默截断。

聊天写作时，在宿主选择 **Super Novel · 小说生成**。`0.1` 宿主须先展开「写作模式」启用预设；`0.2` 宿主随插件注册，不需要写入预设目录。两种方式都不改变默认模式。聊天回复不会自动写入章节，需要手工保存。

只读会话可以查看正文，不能创建或保存。需要写入时使用宿主允许写 workspace 的会话；插件不会自动改变权限。

## 数据位置

「更多」中的「事实与文风」可以把选中的已保存正文授权为叙述或人物对白样本，记录来源说明；人物对白需指定同书人物。生成时主动勾选后才使用，撤销授权或改变来源后停止使用，依赖候选过期。撤销停止后续调用，不删除已有历史或已经发给模型的内容。

「更多」中的「导入与导出」接受 UTF-8 Markdown/TXT，最大 8 MiB，单章仍限 4 MiB。先查看标题分章或单章预览，再导入新作品；原文件不修改，事实尚未分析。中断时先恢复作品，再用相同请求继续。导出选择正文或普通资料，不包含事实、文风授权、审校和保存记录。插件格式保留正文边界与哈希，可逐字回读；修改边界头需重新核对。

`0.2` 宿主由插件注册并管理写作模式，不创建用户预设文件。以下预设目录说明仅适用于 `0.1` 宿主。

旧宿主启用时，插件向第一个 `trust: user` 预设根写入 `dsh-super-novel/`。默认通常为 `$DSH_HOME/.agent-presets/dsh-super-novel/`；未设置 `DSH_HOME` 时通常位于 `~/.dsh` 下。自定义根支持绝对路径和 `~/`，相对路径会被拒绝。

预设目录内只有 `preset.yml`、`agent.cordis.yml` 和归属记录 `.dsh-super-novel.json`。

作品默认保存在当前 workspace 内。在「更多」展开「保存位置」可输入已存在的绝对目录；有原生选择器的宿主也可点击「选择目录」。作品放在该目录的 `novels/` 下。「打开保存目录」调用宿主文件管理器，没有作品时打开根目录。无桌面的宿主显示路径供复制。

点击「切换资料库」前会保留当前草稿，失败时不切换。原目录和作品保留，可从「之前的保存位置」选回；「填入默认位置」只填入路径，再点击切换。当前会话的工作目录不变，保存位置偏好记录在工作目录的 `.super-novel/storage.json`。只读不能修改位置；工作区写入模式只能选工作目录内的位置，外部目录须获得宿主相应权限。拔掉外部磁盘后仍能打开设置切回默认位置。不同根目录的候选和审校不能直接跨库使用。

作品目录：

```text
novels/<作品ID>/
  project.json                    # 标题、章节目录和版本
  chapters/<章节ID>.md             # 正式正文
  drafts/<章节ID>/<编辑分支ID>/   # 已确认的磁盘草稿检查点
  transactions/<操作ID>.json       # 已完成保存记录及原稿
  proposals/<候选ID>.json          # 基线、授权选区、要求、资料和候选
  conflicts/<记录ID>.json          # 保留的本地稿和磁盘稿
  recoveries/<操作ID>.json         # 显式处理的原中断记录
  fact-proposals/<候选ID>.json     # 未采纳的事实与摘要候选
  reviews/<审校ID>.json            # 审校文本、依据快照和问题
  intents/<章节ID>/<版本>.json     # 已保存本章意图
  intent-proposals/<候选ID>.json   # 未采纳的场景方向
  story-state/<版本>.json          # 作者确认的事件、人物变化和伏笔
  story-proposals/<候选ID>.json    # 待确认的本章变化建议
  pending.json                    # 仅未完成保存时存在
```

建书中断时还可能存在 `novels/<作品ID>.creation.json`。不要直接改索引或保存记录来绕过版本检查。备份时复制整个作品目录；有未完成创建时也保留对应创建记录。候选和审校绑定原 workspace，恢复完整记录需使用相同 workspace 路径。迁往其他 workspace 时，通过导出、导入转移正文和普通资料，重新生成候选与审校。

未保存输入先放入浏览器异步存储，再自动保留磁盘检查点。停止输入约一秒后尝试，持续输入约五秒尝试一次；网络和磁盘速度会影响实际时间。状态显示「草稿已存到磁盘」才代表收到落盘回执，时间可在状态提示中查看。草稿不增加正式正文版本，也不更新事实。不同编辑窗口保留独立分支，旧回执不会清除新输入。

「恢复草稿」列出浏览器与磁盘中的分支，先预览，再恢复到编辑区，最后手动保存。正文基线已变时先保留两份并合并。读取磁盘版本会先保留当前输入，历史检查点不会删除。存储或连接失败会提示，可重试、正式保存或下载草稿；不要在失败提示时清除浏览器数据。只查看侧栏不创建目录或调用模型。已确认的磁盘草稿可以在清除浏览器数据后恢复，尚未确认的最后输入、真实断电或坏盘仍可能丢失；请保留独立备份。

## 正文冲突与恢复

- 在「正文历史与恢复」选择已保存版本，查看新旧稿对照。正文无未保存改动时，确认「恢复为新版本」；原历史保留，版本号继续增加。
- 外部编辑后点击刷新或重新聚焦窗口，正文会重新读取。若已有本地草稿，在「保留稿与合并」点击「保留两份稿」，核对后选择磁盘稿、本地稿或手工编辑合并正文。磁盘再次变化时先重新保留两份稿。
- 保存前发现版本或哈希改变时拒绝覆盖，本地草稿仍保留。已读取的外部编辑可以保存为新版本。
- 出现「恢复未完成的保存」时，点击恢复。只有文件符合记录中的旧版或新版，才继续完成保存；出现第三种内容时停止并保留现场。展开「中断保存的两份稿」，读取并核对恢复稿，确认正文后再完成恢复。原中断记录保留在 `recoveries/`。
- 候选过期后可沿用原要求，保存当前正文并重新生成；改写任务须重新选择范围。
- 提示忙碌但宿主已经退出时，先备份作品并确认所有写入进程都已退出，再用 `rmdir` 移除空的 `novels/<作品ID>/.write.lock/`；建书锁位于 `novels/.create.lock/`。不要抢占运行中的锁。

多文件保存不是跨文件原子事务。锁只协调本插件实例，外部编辑器不使用该锁；不要让外部程序与插件同时保存同一文件。普通冲突检测和阶段故障已测试，不宣称能抵御恶意目录替换或所有断电情况。不自动合并正文；真实磁盘满、断电和其他平台故障仍需验收。

## 启用失败

安装或加载失败时，在实际 profile 目录执行：

```sh
node node_modules/dsh-super-novel/scripts/doctor.mjs
```

诊断检查 Node、bundle、编译文件和已解析依赖版本；在 profile 目录执行时还检查插件与宿主是否共用同一 peer 实例。命令只读、不联网、不调用模型。支持的宿主范围为 `^0.1.5-rc.2 || ^0.2.0-rc.2`；旧预设服务与新注册服务至少提供一种。缺依赖时用宿主插件管理器在相同 profile 重装；版本不符时核对安装，不手工绕过兼容检查。自建 profile 应避免混入另一版本的宿主依赖。诊断通过不代表会话服务、权限或模型连接正常。

以下预设目录故障仅适用于 `0.1` 宿主。`0.2` 中模式不可用时，检查宿主插件诊断及同名预设冲突，再重新加载插件。

| 情况 | 处理方法 |
| --- | --- |
| 同名目录不属于插件、存在额外文件、文件被修改或版本不同 | 备份整个目录并检查差异。需要重装时，将旧目录移到预设根之外，再启用 |
| 归属记录有效，只缺少部分文件 | 点击「继续启用」 |
| 文件只写了一部分、归属记录损坏或缺失 | 保留并备份现场，将旧目录移出预设根后重新启用 |
| 提示正在启用，实际进程已退出 | 确认所有启用进程已退出，再用 `rmdir` 移除预设根下的空 `.dsh-super-novel.lock/` 目录 |
| 没有可写用户根或使用相对路径 | 检查宿主 roots 配置；插件不会自动修改配置 |

锁用于协调插件实例。不要在其他实例启用时移除锁。写入不是跨文件事务，中途失败会保留现场；路径检查不覆盖所有祖先目录，也不抵御其他程序同时替换文件。

## 升级

本地作品沿用 schemaVersion 1，旧章节不需要格式转换。升级前关闭所有写入实例并备份整个 `novels/` 目录，包括候选、事实、审校、导入与未完成记录。旧版应用不支持新文档类型时不要降级写入；未知高版本会拒绝处理。

`0.1` 宿主不自动迁移预设。先关闭使用旧模式的会话，备份旧预设并将其移出预设根；安装新包后重新启用，再对照备份处理自己的修改。不要修改归属记录来绕过冲突保护。

`0.2` 宿主升级后重新加载插件即可注册写作模式。由 `0.1` 升级到 `0.2` 时，旧预设文件和作者修改不会自动导入新注册表；先备份，使用宿主配置管理自己的预设。同一 workspace 的作品继续保留。

## 卸载

1. 关闭使用小说生成模式的会话。
2. `0.1` 宿主须将用户预设目录备份并移到所有预设根之外；`0.2` 宿主无需此步。
3. 从安装时使用的 profile 移除插件，例如：

   ```sh
   dsh plugin --profile web remove dsh-super-novel
   ```

官方插件命令会同步 profile 的 bundle 清单。若手动管理 profile，还需移除 `dsh.profile.bundles` 中的 `dsh-super-novel`。

`0.1` 宿主先卸载包会留下引用缺失包的预设，可能显示不可用。重新安装相同版本可以恢复，也可按上述步骤移走残留预设。`0.2` 宿主在插件卸载时撤销注册，已有会话的模式生命周期由宿主管理。两种方式都不会删除 workspace 中的作品。

## 整书备份

「更多 → 整书备份与恢复」可手动备份、选择已有绝对目录、打开备份文件夹。写作期间有改动时，每 15 分钟尝试一次；失败不会更新最近核验成功时间。正文、资料、磁盘草稿、候选、事实、文风授权、审校、历史和恢复记录均保留，宿主配置和聊天不在包内。

手工保存、AI 采纳、事实采纳、意图与状态确认、导入和历史恢复都会安排备份。同一作品的多次操作合并到一次尝试；关闭宿主前尚未执行的定时备份不会补做，重要改动后可手动备份。

选择一份备份先核验和查看清单，再恢复为新副本。复制上方新路径，在保存位置中切换。原库保持原样；源库绑定的候选、审校和草稿保留来源身份，不能跨库直接采纳。普通导出只提供可读文稿，不能替代完整备份。

备份是标准 tar.gz，可用系统解压工具打开。单文件上限 32 MiB，整包内容上限 1 GiB、50,000 文件；超限或损坏会拒绝，不发布不完整包。备份默认保留全部副本。建议选另一磁盘，并另留一份离机副本；同盘备份不能抵御坏盘。

## 维护资料

打开「资料库」后可按正文内容、名称、别名搜索，或筛选类型、标签、关联章节、收藏和状态。选一份资料先查看保存内容；「标签、关联与状态」中修改元信息，正文由「编辑这份资料」进入。归档和回收站保留文件、ID、历史与引用，恢复后继续使用。移入前会列出引用、草稿和生成影响；旧任务快照保留，新任务不能选用。

旧作品首次启用资料库会先完整备份，再升级为格式 2。只读操作不会迁移；旧插件拒绝格式 2，Markdown 可外部读取。中断后通过作品恢复入口完成日志发布。

已保存正文选区可「选区存为资料」，保留原文、版本和来源。资料页「AI 整理候选」可结合关联资料整理、建议标签或指出冲突，采纳后才更新内容，来源资料保留。设定与计划不等于正文事实。来源与引用版本面板分别显示手工关联、生成实际使用版本和事实证据。

「资料」中有本章、收藏、固定和最近入口；固定和最近记录按作品保存在当前浏览器，删除缓存会丢这些偏好，但不影响资料正文。参考搜索可匹配资料正文，日常查资料不调用模型。底部前后章按钮切章前确认草稿，选区 AI 明确显示修改范围；当前有未保存稿时先保存。字体、行距和宽阅读区在「更多 → 写作外观」设置。


## 本章意图与局部审校

在「更多 → 本章意图」写目标和视角，按需补阻力、选择、代价、结尾变化与硬约束。所有字段都可跳过，意图单独保存，关闭抽屉保留输入。磁盘保留每次意图版本，整书备份包含它。未保存的意图输入只在本机浏览器中保留，仍需点击保存。

「AI 建议方向」每次只调用一次，给 1–3 个方向。选择方向后可以修改，保存才更新意图；正文不随之改变。生成设置中可选择已保存意图、资料、最多三章前文和授权文风。点击「预览本次上下文」查看实际内容、来源和字节预算，不调用模型。硬约束不自动裁剪，超过预算时减少其他输入或拆任务。事实仍按人物/读者知情范围选取。

先在正文选段，再从「更多 → 审校」勾选「只审校当前选区」。问题必须引用范围内原文；局部修订只替换该问题引用，仍需作者采纳，最多两轮。阻断问题全部显示，其余先展示三个，可展开。机械检查会提示重复段落，可以把有意重复列为例外。引用位置校验不等于语义正确，模型评语不保证文学质量。

## 时间线、人物状态与伏笔

先保存正文并选中片段，再打开「更多 → 时间线、人物状态与伏笔」。点击「选区记录事件」，填写名称，按需加入人物位置、伤势、物品或知情变化，核对引用后确认保存。记录独立于人物卡与正文；关闭抽屉保留当前表单，刷新前请确认保存。

默认按叙事顺序展示。只有作者明确填写时间说明和顺序编号后，才按故事顺序排列；未知时间保留为未知，排在已知时间后。倒叙不自动推算日期。可以筛选某个人物的变化。

「AI 建议」每次一次调用，只整理当前保存章节。建议先存到待确认列表；选一项后可以改名称、人物变化或引用，确认保存才进入账本。模型不能自动宣布伏笔已回收。引用校验只能核实位置，事件含义仍需作者判断。

「伏笔」可先记录计划。改为已出现或待回收时，须用正文选区确认埋设；改为已回收时，还须选中回收片段。两处可以位于不同章节，回收不能排在埋设之前。核对引用时可返回对应章节，再打开面板继续编辑。

生成设置可勾选已确认前章状态，选择读者或人物知情范围。人物范围仅包含该人物的确认变化，不带其他人物的混合引用、事件标题或读者伏笔。未来回收和未发生计划不参与。来源过期或状态超过 128 KiB 会阻止依赖它的生成；可先预览上下文。

「本章修改影响」只读列出依赖本章的事实、摘要、资料来源、候选、审校、事件与伏笔。改稿后逐项核对，记录可用当前选区重新确认；人物卡不会被自动覆盖。列表超过读取预算会显示不完整，未登记的依赖仍需作者检查。跨库恢复保留这些记录的原库身份，不能直接作为新库的有效上下文。
