# 使用说明

安装步骤见 [README](../README.md#安装)。以下说明适用于当前技术预览版。

## 启用与写作

打开会话，在右侧栏开始页选择「小说生成工作台」，点击「启用小说生成模式」。随后在宿主模式选择器中选择 **Super Novel · 小说生成**；列表未更新时关闭后重新打开。

在聊天中说明要规划、起草、续写还是润色，并提供必要的设定或原文。局部修改时明确目标段落和必须保留的内容。当前插件只提供提示词指导，不会自动检查字数、保存正文或运行独立审校。

## 数据位置

启用时，插件向宿主第一个 `trust: user` 预设根写入 `dsh-super-novel/`。默认通常为 `$DSH_HOME/.agent-presets/dsh-super-novel/`；未设置 `DSH_HOME` 时通常位于 `~/.dsh` 下。自定义根支持绝对路径和 `~/`，相对路径会被拒绝。

目录内只有 `preset.yml`、`agent.cordis.yml` 和记录版本、文件哈希的 `.dsh-super-novel.json`。插件不保存小说正文。只查看侧栏不会创建目录或调用模型，也不会改动预设 roots、默认模式或其他预设。

## 启用失败

| 情况 | 处理方法 |
| --- | --- |
| 同名目录不属于插件、存在额外文件、文件被修改或版本不同 | 备份整个目录并检查差异。需要重装时，将旧目录移到预设根之外，再启用 |
| 归属记录有效，只缺少部分文件 | 点击「继续启用」 |
| 文件只写了一部分、归属记录损坏或缺失 | 保留并备份现场，将旧目录移出预设根后重新启用 |
| 提示正在启用，实际进程已退出 | 确认所有启用进程已退出，再用 `rmdir` 移除预设根下的空 `.dsh-super-novel.lock/` 目录 |
| 没有可写用户根或使用相对路径 | 检查宿主 roots 配置；插件不会自动修改配置 |

锁用于协调插件实例。不要在其他实例启用时移除锁。写入不是跨文件事务，中途失败会保留现场；路径检查不覆盖所有祖先目录，也不抵御其他程序同时替换文件。

## 升级

当前版本不自动迁移预设。先关闭使用旧模式的会话，备份旧预设并将其移出预设根；安装新包后重新启用，再对照备份处理自己的修改。不要修改归属记录来绕过冲突保护。

## 卸载

1. 关闭使用小说生成模式的会话。
2. 将用户预设目录备份并移到所有预设根之外。
3. 从安装时使用的 profile 移除插件，例如：

   ```sh
   dsh plugin --profile web remove dsh-super-novel
   ```

官方插件命令会同步 profile 的 bundle 清单。若手动管理 profile，还需移除 `dsh.profile.bundles` 中的 `dsh-super-novel`。

先卸载包会留下引用缺失包的预设，宿主可能显示不可用。重新安装相同版本可以恢复，也可按上述步骤移走残留预设。插件没有自动卸载清理钩子。
