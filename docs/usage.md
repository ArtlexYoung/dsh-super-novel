# 使用说明

安装步骤见 [README](../README.md#安装)。以下说明适用于当前技术预览版。

## 启用与写作

打开带本地 workspace 的会话，在右侧栏选择「小说工作台」。输入作品名并新建作品，再输入章节名并新建章节。章节可改名、上移或下移；标题改变不会改变正文文件身份。

在章节编辑区写正文，点击保存。预览按原文显示，不执行 HTML。换会话、关闭侧栏或重启后，打开相同 workspace 即可读取作品。正文单章上限为 4 MiB UTF-8，作品最多 10,000 章；作品索引上限 4 MiB，单次保存记录上限 32 MiB。超限会拒绝处理，不截断。

先保存正文，在「生成候选」选择起草、续写、选段改写或润色，填写写作要求并生成。改写、润色只替换正文中已选中的文字。参考资料可主动填写，生成只读取这些资料和目标正文，不读取其他作品或聊天历史。

查看「候选正文」或「改动对照」，再采纳或拒绝。候选在采纳前不改变正式正文；正文版本变化后候选过期。生成可停止，关闭侧栏或切换会话不会改任务归属。宿主退出后未完成任务不自动重发，收到的内容仍保留。空输出、截断和未完成候选不能采纳。

「资料与规划」可建立故事种子、书卡、人物、世界、总纲、章纲和场景；章纲与场景可关联章节。字段模板可以删改，允许直接起草，不强制填完整资料。资料也有保存、历史和候选采纳。生成前展开「选用已保存资料」并勾选；只读取同书选中资料。空资料或未登记的外部修改会阻止生成。规划仍是未来安排，不是已发生事实。

在「事实与摘要」显式提取候选，核对引用和知情范围后采纳；也可选择原文手动添加事实，局部回填不会算成全章完成。引用可定位回正文。提取不会修改正文，未采纳内容不进入事实。引用匹配不能证明语义正确，仍需作者核对。旧章改变后事实过期，需要重新提取。

生成下一章时可开启「使用前章事实」，选择读者或人物知情范围。读者事实不会自动进入人物知识，人物范围不使用读者摘要。缺失/过期回填或事实超过 128 KiB 时阻止该生成；关闭此选项时不保证长篇连续性。原文中的伤势、时间线、秘密等由事实候选表示，不宣称模型能完整识别全部信息。

在「审校与修订」选择已保存正文或待采纳候选，设置字数/段数范围后开始审校。字数是非空白 Unicode 码点数，段落按空行分隔；0 表示不设上限。模型分别检查连续性、人物、因果和语言，问题必须带匹配原文的引用。可定位原文、生成局部修订、查看改动、再次审校，再采纳。每条候选修订链最多两轮，不自动覆盖正文。没有资料、检查失败或未完成时明确显示依据不足或未知；未发现问题也不保证文学质量。

生成和审校使用当前会话的模型与宿主连接，不在浏览器配置凭证。单次输入上限 256 KiB UTF-8（包含正文、要求和资料），最多输出 8192 tokens，五分钟超时；超出输入范围会拒绝调用，不静默截断。

聊天写作时展开「写作模式」，启用 **Super Novel · 小说生成** 后在宿主中选择该模式。聊天回复不会自动写入章节，需要手工保存。

只读会话可以查看正文，不能创建或保存。需要写入时使用宿主允许写 workspace 的会话；插件不会自动改变权限。

## 数据位置

「资料」页签可以把选中的已保存正文授权为叙述或人物对白样本，记录来源说明；人物对白需指定同书人物。生成时主动勾选后才使用，撤销授权或改变来源后停止使用，依赖候选过期。撤销停止后续调用，不删除已有历史或已经发给模型的内容。

「导入与导出」接受 UTF-8 Markdown/TXT，最大 8 MiB，单章仍限 4 MiB。先查看标题分章或单章预览，再导入新作品；原文件不修改，事实尚未分析。中断时先恢复作品，再用相同请求继续。导出选择正文或普通资料，不包含事实、文风授权、审校和保存记录。插件格式保留正文边界与哈希，可逐字回读；修改边界头需重新核对。

启用时，插件向宿主第一个 `trust: user` 预设根写入 `dsh-super-novel/`。默认通常为 `$DSH_HOME/.agent-presets/dsh-super-novel/`；未设置 `DSH_HOME` 时通常位于 `~/.dsh` 下。自定义根支持绝对路径和 `~/`，相对路径会被拒绝。

预设目录内只有 `preset.yml`、`agent.cordis.yml` 和归属记录 `.dsh-super-novel.json`。

作品保存在当前 workspace 内：

```text
novels/<作品ID>/
  project.json                    # 标题、章节目录和版本
  chapters/<章节ID>.md             # 正式正文
  transactions/<操作ID>.json       # 已完成保存记录及原稿
  proposals/<候选ID>.json          # 基线、授权选区、要求、资料和候选
  conflicts/<记录ID>.json          # 保留的本地稿和磁盘稿
  recoveries/<操作ID>.json         # 显式处理的原中断记录
  fact-proposals/<候选ID>.json     # 未采纳的事实与摘要候选
  reviews/<审校ID>.json            # 审校文本、依据快照和问题
  pending.json                    # 仅未完成保存时存在
```

建书中断时还可能存在 `novels/<作品ID>.creation.json`。不要直接改索引或保存记录来绕过版本检查。备份、迁移作品时复制整个作品目录；有未完成创建时也保留对应创建记录。

未保存输入保存在浏览器本地，按 workspace、作品和章节隔离。浏览器拒绝存储或容量不足时会提示，请立即保存或下载本地草稿。正式正文和保存记录在磁盘上，不依赖聊天历史。只查看侧栏不会创建目录或调用模型。

## 正文冲突与恢复

- 在「正文历史与恢复」选择已保存版本，查看新旧稿对照。正文无未保存改动时，确认「恢复为新版本」；原历史保留，版本号继续增加。
- 外部编辑后点击刷新或重新聚焦窗口，正文会重新读取。若已有本地草稿，在「保留稿与合并」点击「保留两份稿」，核对后选择磁盘稿、本地稿或手工编辑合并正文。磁盘再次变化时先重新保留两份稿。
- 保存前发现版本或哈希改变时拒绝覆盖，本地草稿仍保留。已读取的外部编辑可以保存为新版本。
- 出现「恢复未完成的保存」时，点击恢复。只有文件符合记录中的旧版或新版，才继续完成保存；出现第三种内容时停止并保留现场。展开「中断保存的两份稿」，读取并核对恢复稿，确认正文后再完成恢复。原中断记录保留在 `recoveries/`。
- 候选过期后可沿用原要求，保存当前正文并重新生成；改写任务须重新选择范围。
- 提示忙碌但宿主已经退出时，先备份作品并确认所有写入进程都已退出，再用 `rmdir` 移除空的 `novels/<作品ID>/.write.lock/`；建书锁位于 `novels/.create.lock/`。不要抢占运行中的锁。

多文件保存不是跨文件原子事务。锁只协调本插件实例，外部编辑器不使用该锁；不要让外部程序与插件同时保存同一文件。普通冲突检测和阶段故障已测试，不宣称能抵御恶意目录替换或所有断电情况。不自动合并正文；真实磁盘满、断电和其他平台故障仍需验收。

## 启用失败

| 情况 | 处理方法 |
| --- | --- |
| 同名目录不属于插件、存在额外文件、文件被修改或版本不同 | 备份整个目录并检查差异。需要重装时，将旧目录移到预设根之外，再启用 |
| 归属记录有效，只缺少部分文件 | 点击「继续启用」 |
| 文件只写了一部分、归属记录损坏或缺失 | 保留并备份现场，将旧目录移出预设根后重新启用 |
| 提示正在启用，实际进程已退出 | 确认所有启用进程已退出，再用 `rmdir` 移除预设根下的空 `.dsh-super-novel.lock/` 目录 |
| 没有可写用户根或使用相对路径 | 检查宿主 roots 配置；插件不会自动修改配置 |

锁用于协调插件实例。不要在其他实例启用时移除锁。写入不是跨文件事务，中途失败会保留现场；路径检查不覆盖所有祖先目录，也不抵御其他程序同时替换文件。

## 升级

本地作品沿用 schemaVersion 1，旧章节不需要格式转换。升级前关闭所有写入实例并备份整个 `novels/` 目录，包括候选、事实、审校、导入与未完成记录。旧版应用不支持新文档类型时不要降级写入；未知高版本会拒绝处理。

当前版本不自动迁移预设。先关闭使用旧模式的会话，备份旧预设并将其移出预设根；安装新包后重新启用，再对照备份处理自己的修改。不要修改归属记录来绕过冲突保护。

## 卸载

1. 关闭使用小说生成模式的会话。
2. 将用户预设目录备份并移到所有预设根之外。
3. 从安装时使用的 profile 移除插件，例如：

   ```sh
   dsh plugin --profile web remove dsh-super-novel
   ```

官方插件命令会同步 profile 的 bundle 清单。若手动管理 profile，还需移除 `dsh.profile.bundles` 中的 `dsh-super-novel`。

先卸载包会留下引用缺失包的预设，宿主可能显示不可用。重新安装相同版本可以恢复，也可按上述步骤移走残留预设。插件没有自动卸载清理钩子，也不会删除 workspace 中的作品。
