# 评测说明

目前只完成小规模技术与写作验证，不能据此宣称质量提升或成本下降。下表是 2026-09-20 的历史结果，不是 `0.0.2` 的重新评测。

| 验证 | 结果 | 详细记录 |
| --- | --- | --- |
| P0 安装与界面 | macOS Web 的启用、状态、预设共存和浏览器检查通过 | [技术验证](P0-VALIDATION.md) |
| 3 个写作样本、6 次任务 | 请求全部完成，机械检查通过；定性审阅仍发现因果问题 | [真实模型对照](LIVE-EVAL-P0.md) |
| 浏览器首稿 | 要求 900–1200 个汉字、6 段，实际 759 个汉字、13 段，未通过 | [浏览器写作](BROWSER-WRITING-P0.md) |
| 浏览器局部修订 | 目标段落 179 个汉字，其余 12 段逐字保留 | [浏览器写作](BROWSER-WRITING-P0.md) |

模型对照使用相同素材和模型：普通助手共 10,873 tokens、50.588 秒，小说预设共 12,260 tokens、51.785 秒。样本太少，无法推断稳定速度或质量差异。首次采集失败的任务用量未知，未算作零成本；完整口径见原报告。

写作质量是主要目标。字数、段数、修改范围可以机械检查，人物、因果、语言和长篇连续性需要进一步评阅。更多 token 可以用于必要上下文和审校，不设必须节省 token 的门槛。

复现技术验证和模型对照的命令分别保留在上述报告中。原始评测资料位于本地忽略的 `eval/`，不随仓库分发；新实验需先准备合成案例、固定条件，再运行。当前没有跨章、多题材、重复采样和多人盲评的充分证据。
